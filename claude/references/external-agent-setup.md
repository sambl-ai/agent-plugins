# Prepare an external agent for a Sambl task

Retain the user's original request and valid choices throughout preparation.
Prepare only the access needed by that request, then continue its product entry.
General help, release history and feedback without file context need no Figma file
or native writer. Setup is not kit onboarding, admission or Apply consent.

Distinguish the connections: the agent's Sambl MCP authorization; its Figma native
provider and file permissions; and Sambl's caller-bound Figma REST access. A success
on one does not establish the others. Reuse working connections and restore only
the boundary that actually failed. Keep credentials in their host-owned sign-in
flow, never in skills, file metadata or chat.

Discover the actual available tools before offering installation. Use the host's
supported official Figma connection when it supplies the required capabilities;
the user completes any access approval. Read-only design-context tools alone do
not establish a native writer. Report actual provider restrictions separately
from general Figma Plugin API support. No design mutation is needed to probe setup.

Resolve the target from the user's explicit file/layer link, a still-valid target
of this task, or an actual explicit selection supplied by the provider. Ambient
browser tabs and recent files alone do not choose a target. Ask for a readable
file choice or link only when it remains unresolved. Keep the actual file and
node identifiers internally and show its name/link in the ordinary workflow.

## Recover access through existing connections

A returned Figma access denial describes that provider/account, not every
connection. Before asking for Can edit, reauthentication or installation:

1. Establish the denied connection's actual account through its supported
   identity tools, such as whoami when available. Reuse fresh task evidence;
   refresh only what is missing or stale. Browser login, Sambl REST success and
   plan/seat alone do not establish native access to this file.
2. Inspect the host's already connected Figma routes and required capabilities.
   Use supported read-only file/access evidence to find a suitable authorized
   route for the same target; stop once the choice is resolved. A screenshot or
   successful read alone does not establish write permission. Preserve an
   explicitly user-selected account/provider; ask before departing from it.
   An agent-selected tool is not an explicit user choice. Otherwise reuse a
   suitable existing route; ask one readable choice if equally suitable routes
   remain ambiguous. Different account emails can be valid for the same file.
3. Only if no suitable existing route resolves access, explain the actual
   account, file and missing permission/capability, then request the smallest
   needed action. Mark unavailable identity/access facts as unknown. Ask for
   Can edit only for the intended account when edit access is actually missing.

The denial itself authorizes no new connection, OAuth grant or account/Share
change. A host approval/policy rejection is a different outcome: retain its
stated restriction and resolve it through the host, not an alternate provider.
An access denial is not proof that the file is foreign or empty.

Resume the same task, file, choices and known results through the working route.
Retain an operation and its preview/decision when supplied. If a write's outcome
is uncertain, reconcile actual state through available status/readback before
further mutation; completed work stays accepted. Access
recovery does not restart Start/Apply or add a user confirmation to an unchanged
approved scope.

## Continue the product task

Follow the selected entry's actual file, admission and result contract.
Palette/Variable Start owns kit admission; add no preceding recognize_kit merely
for setup. Native Collections resolves the actual file and collections as needed;
other native entries retain their declared admission. Prefer supported server
REST facts and obtain remaining native observations when useful. Enterprise
Variables REST is outside public requirements.

Continue the user's task with the host's applicable confirmation when needed.
Connection/install approval supplies no product choice. Retain accepted results
across reconnect. Where an operation supplies status/readback, reconcile that
same operation; after a lost Start reply, use its scoped lookup when supplied.
Do not repeat consumed Start/Apply to regain context. A changed file needs fresh
context and the selected route's admission/consent; old work stays with its file.
Keep this readiness evidence in the task context, not a new journal or datastore.
