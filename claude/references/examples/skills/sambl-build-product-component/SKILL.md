# Build a product component

Reuse the [entry skill](../sambl-examples/SKILL.md) admission and still-applicable
usable-foundation check for this actual file and requested run; preserve its
Sambl/adapted mode in nested work. If this skill
is entered directly, load and follow the entry first; do not repeat its dialogue.
Matching component or mode names are not Sambl identity. No page creation or
component writes precede this gate.


Use this process internally for each missing component in the selected screen's
dependency order. The user names the screen, not its component inventory. Do not
ask the user to load instructions, supply technical IDs or accept each source.

Read [delivery](../../references/delivery.md), the [native authoring protocol](../../references/portable-build-protocol.md),
the [Figma adapter](../../references/figma-agent.md), [current context](../../specs/current-context.md),
and this component's full WHAT and required kit consumption contracts before its writes.
Retain already delivered instructions; do not reread the whole package per component.

Resolve the actual destination, sources, variables, styles and retained modes
locally. A historical ID or a matching screenshot is not a source identity.
Check exact public APIs, native tuples, source ancestry and current bindings.
Reuse a compatible complete owned source unchanged after checking its actual
state against the current relevant component contract. A different delivery
packageVersion alone is not an incompatibility; do not require an old package to
check current API, bindings, structure and behavior. Partial, ambiguous, unreadable,
user-edited, unknown-ownership or actually incompatible output needs a focused
disposition; do not delete or silently replace it. Create only the missing
selected source.

Preserve kit masters, tokens, styles, mode inventory and existing consumers.
Resolve missing preferred dependencies by the shared substitution policy in
delivery.md: suitable kit alternatives, then honest owned variable-backed content.
Warn about differences; a preferred-source loss alone is not a reason to stop.
Required native behavior, Slots and semantic roles still must be real.

Use the current Auto Layout. Keep available kit instances linked. Use public
properties and only the consumer overrides authorized by both contracts. Select
native tuples before inserting Slot content. Matching inherited fields are read
assertions, not setters. Load actual fonts before permitted text edits.

Create a native Slot before using its automatically created SLOT definition;
never pre-add a duplicate or fake it with a Frame. Follow the component's bounded
shared-key consolidation procedure exactly. Preserve all pre-existing settings,
preferences and defaults. Reacquire after writes; verify actual native validity.
Do not swap populated Slot-bearing instances or bypass provider restrictions.

Self-check identity, public property order/defaults, actual variants, links,
bindings, content, Slot backings/settings/validity and settled geometry using
[final checks](../../specs/acceptance.md). Then continue to the next dependency
and screen in this same requested run. No Codex receipt, independent reviewer or
user approval between components is needed. A real unresolved requirement stops
only dependent work; preserve and clearly report what remains incomplete.
