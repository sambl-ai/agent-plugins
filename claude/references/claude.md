# Sambl in Claude

This plugin installs the product instructions locally. Read the selected workflow
and only the supporting material needed for the user's request. Use
[the reference index](reference-index.json) to resolve reference names, paths and
exact canonical versions. Resolve an instruction-only get_reference load to its
indexed local file when that revision is present. The entry's supplied
reference/version context applies to child loads. Do not refetch an already
loaded entry. Local delivery replaces the Figma Agent choice adapter with these
Claude host rules; the index retains source and projected hashes.

For Desktop/Cowork, use the plugin registered in the active account/org local
marketplace store and its connector in Settings → Plugins. Code uses its own
profile and `/plugin` / `/mcp`. An install in one profile does not establish
installation in the other; preserve the selected host and connection.

Live get_capabilities, recognize_kit where the entry requires it, calculations,
proposals, supplied operation status/reporting and feedback remain actual Sambl
MCP calls.
Use only the environment/server/URL declared in the index. Claude Code may qualify
plugin MCP tool names; resolve the tools actually loaded from this plugin's
connection instead of assuming a Codex namespace or a standalone server name.
Local skills do not grant access or replace the authorized capability list.
A missing matching reference may use the existing get_reference fallback at its
exact canonical version. Reconcile version mismatches through the normal update
path without mixing revisions or replaying completed changes.

Load missing native dependencies through the supplied versioned references and
continue the same task. A delegated native task receives its goal, relevant facts,
preservation criteria and needed references. When an entry supplies an operation,
Sambl retains its state and the caller uses the supplied completion request.

Examples still obtains the live catalogue/packageVersion through
get_example_package. Retain the user's choices and the same conversation. Use
the requested version for dynamic calls and matching indexed local material.

For missing Sambl/Figma access, a returned Figma access denial or an unresolved
working file, use
[external-agent preparation](external-agent-setup.md), retaining the original
task. Follow its account/existing-connection fallback before asking for Can edit
or reconnecting. Discover existing Figma plugin/connector and MCP tools through
the active host's available inventory; a server name or tool prefix does not
select the correct account. Sambl and Figma are independent connections. Follow
the actual provider's maintained skills and restrictions.
A reader or screenshot does not establish a native writer. Do not transfer
another host's API availability or payload limits to this Claude host. Use the
current provider's limits and actual invocation/readback evidence; preserve
existing progress after an uncertain write before considering a retry.

For collection discovery, a compact summary of names, modes and variable counts
is usually enough to start. Fetch selected IDs and definitions as they become
relevant. Return compact objects directly from native reads and let the tool
serialize them.

A host approval/policy rejection is distinct from a returned Figma access denial
or connection loss. Retain its stated authorization restriction and resolve it
through the host before another dependent write; switching provider does not
remove that rejection. Existing user authority or new evidence can resolve the
stated concern; a recovery response supplies no permission.

Use the current Claude host's available question interface or a direct chat reply for
missing material product choices. A clear bounded instruction or accepted plan
can authorize its covered effects within host permissions, including Apply when
that route supplies it. For expanded scope or a required approval, show the
concrete proposal and wait for the user's decision. External Send always needs
its concrete preview decision. Tool permission and generated consent flags are
not product decisions. A verified no-op needs no Apply question. Do not claim
an unresolved native confirmation was answered unless the host resolves it.

An installed skill, available tool, successful OAuth and verified file outcome
are different evidence. Report only what was observed. Restore failed
connections and resume the same task. If installation requires restarting
the host, preserve a compact description of the task, selected target and
known result for continuation.
