# Examples delivery and entry

The Agent plans and builds requested screens/components with a final self-check;
no test operator or independent reviewer is required. Sambl Web App Design owns
specifications. The kit supplies local primitives/variables; never inspect or
clone its former Examples page as a recipe.

Use the pinned documents from the screen_package returned by get_example_package.
Read the assembly skill and common references once, then the selected screen and
kit contracts. Read each component WHAT just before building or reusing that
component, retaining earlier complete instructions and their versions. Resources
and get_reference deliver identical bytes. Resources must match the package's exact
versioned URI; tool responses must match its listed reference/version. For unresolved Resource URIs
use the supplied fallback with exact expectedVersion. Relative links, summaries
and unversioned memories are not pinned documents. Retry failed/truncated delivery
once when safe; never refetch successes or replay work. Version drift pauses
dependent work for the entry's fresh-package recovery, retaining choices and
completed work. No history; never silently remove a pin to load another version.
No local repository, Cloudflare Tunnel, test context, hash receipt, measurement
prompt or separate preload message from the user is required.

## Entry and local file mode

The [entry skill](../skills/sambl-examples/SKILL.md) owns selection, exact native
recognition, usable-foundation gate, Adapt/Cancel and package retrieval after
the answer. Reuse its completed admission and still-applicable foundation evidence
only within the same actual file and selected request.
Do not repeat its question during component construction. Recognition is identity
metadata evidence, not design integrity. A read error never means absent metadata.
The current build mode remains local to the Agent; package retrieval does not
authenticate the canvas or grant writes. Canonical and adapted construction use
the same target specifications with the entry's explicit adaptation qualifications.
An empty file, no suitable COLOR variables or no applicable text styles stops
before adaptation or any writes. Adapt never authorizes building that foundation;
no new variables/styles or literal formatting substitutes for it. After reading
the selected WHAT, resolve the exact required roles through existing suitable
variables/styles before dependent writes. One deleted preferred dependency is
handled by the substitution policy while a suitable overall foundation remains.
The package baselineProfiles describe scenario composition templates, not the
actual modes; read actual axes from the file.

## Check the Slots used by this output

Examples does not run full source Slot preparation or restore all kit defaults.
That remains a separate task and part of onboarding. Preserve existing source
settings, default content, preferred lists and unrelated user changes.

Resolve the selected dependency's actual public Slot definition/backlink and
required local content family. Read current settings and the populated consumer's
native limitViolations under the shared build protocol. Native consumer validity
is required; neither a preparation receipt nor an exposed preferred key alone
proves it. Manual or unknown recommendations outside this dependency closure are
nonblocking information, not another repair question.

A required source's structural error, unreadable identity or actual consumer
violation stops its dependent work with the observed reason. Do not weaken its
restrictions or rewrite its defaults to make the example pass. A dependency
proved absent follows the general substitution policy below; absence is distinct
from an unreadable or incompatible surviving source. Retain any earlier Slot
preparation result with its real scope, without rerunning it or declaring the
whole file configured.

## General missing-dependency policy

This policy applies within the file mode already admitted above. It never
authorizes automatic adaptation of an unrecognized file.

Resolve the exact current local component, icon, style or typed token first.
Prove absence in its relevant catalogue; an unreadable, ambiguous or restricted
object is not absent. Prefer a suitable available kit alternative, then an honest
owned composition using available kit variables and components. Preserve meaning,
content, native behavior and current-mode compatibility. Missing nonessential
decoration may be omitted without an empty spacer. Never invent a brand asset,
fake a native Slot, detach, import remote primitives, edit kit masters or create
shared variables/styles. Bind available semantic tokens rather than copying HEX,
pixel sizes or font metrics. Disclose replacements before affected work when
known and in the result; this information alone requires no extra approval.
Distinguish a required semantic identity/media role from its preferred graphic.
Keep an available exact original source preferred. If it is proved absent, use a
suitable actual local asset or owned inert identity text, styled with the existing
color variables and text styles, only when the required meaning is preserved.
Disclose lost exact visual/source parity; never invent a brand graphic, lookalike
or fetched replacement. Omit only nonessential decoration. This shared rule
applies to any missing identity/media role, not a per-component fallback list;
keep the explicit adapted qualification in an adapted build.

If no safe compatible construction supplies required meaning or native behavior,
report blocked/incomplete: list actual blocking missing/unsuitable components or
other dependencies by human-readable name, plus unbuilt parts. Preserve completed
work. Unreadable/restricted/ambiguous is not missing. Do not force a substitute or
claim success with unmet requirements.

## Static examples, not live actions

No Example requires real URLs, hyperlinks or working actions. Keep specified
link-like text and its token/style treatment as inert text; do not request or
invent Terms/Privacy URLs, OAuth, clipboard services, navigation destinations or
other product integrations. Preserve unrelated existing user content. This rule
does not suppress the official Community link or native links to generated Figma
results, which remain useful outside the generated static example.
