# Generate an example screen

The [entry skill](../sambl-examples/SKILL.md) already owns the screen choice,
file recognition, usable-foundation check, adaptation question and package
retrieval. Reuse its local file/screen/build mode and still-applicable foundation
evidence; do not repeat the dialogue or call a workflow coordinator. If this
skill is entered directly without that complete applicable entry context, first
load and follow the entry, including its delivery-context recovery. Do not create
pages/Sections or make screen/component writes before its gates.
A normal complete entry and screen package need no extra entry lookup.
Build only the selected Sign In or Dashboard WHAT. Dashboard retains its specified
canvas content; never invent charts, metrics or a different screen.

Read the [delivery guide](../../references/delivery.md), [native protocol](../../references/portable-build-protocol.md),
[Figma adapter](../../references/figma-agent.md), [current context](../../specs/current-context.md)
and selected screen WHAT/content. Resolve the actual file and environment.
Resolve the needed sources, tokens, styles, content and actual mode mappings
once, retaining fresh observations across specimens. Derive the dependency
closure from [component plan](../../specs/component-plan.md).
Build missing sources with [component skill](../sambl-build-product-component/SKILL.md),
checking each yourself before dependent construction. Do not stop at components
or require the user to list them, send another prompt or obtain Codex acceptance.

Use a page named exactly Examples, with native Product Components and Examples
Sections. Each screen root is its linked product shell instance, not a redundant
Frame. Create only the selected screen across all actual retained breakpoints,
or one specimen with no synthetic Size Class when the axis was removed. Preserve
current themes/platforms and existing compatible output; do not restore modes.
Reuse the common composition/content across specimens, adapting the exact shell
tuple, modes and layout required by each retained breakpoint under the shared
build protocol. Mode changes alone do not replace the specified Grid/Wrap or
content differences. Full source Slot preparation is not part of this build.

Keep source defaults read-only during assembly. Resolve the real consumer Slots
through public definitions/backlinks. Select the final shell tuple before filling
it. Prepare owned content before insertion and reacquire afterwards. For md/lg
Dashboard follow its explicit Grid order: configure native Grid and FILL/HUG
cards with minWidth224 and clipsContent=false before inserting the composition
into the real Main Slot; after insertion change only the composition root to FILL.
Do not repair nested card geometry through an inherited descendant.

Apply the general kit substitution rule for anything proved missing. Use actual
kit tokens/styles for owned replacements, retain other links, and disclose the
specific substitution or omission. Missing required functional meaning, an actual
provider restriction or unresolved data remains a real issue, never a fabricated pass.

Finalize native Section presentation last, including bound fill, stroke color,
stroke width and corners; no extra Surface. Self-check the selected screen and
its required sources using [final checks](../../specs/acceptance.md), including
settled text fit, real source links, modes, Slots and Grid clipping. Take an
overview screenshot when supported. Do not perform unrelated whole-file audits.

Finish with a concise result in the user's language, links to the screen and
Product Components, and an invitation to view the result. List actual substitutions,
unchecked limitations or build problems. No server report submission, validation
handshake, mandatory “accept” button or Codex review is part of this workflow.
If execution was interrupted or a required part failed, say exactly what was
created and what was not; do not call incomplete output finished. Never start
another screen or replay construction automatically.
