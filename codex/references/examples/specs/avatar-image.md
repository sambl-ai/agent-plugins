# Avatar — current Image default contract

The user explicitly selected the current default kit Image picture instead of
the historical personal avatar. This overrides exact-reference photo fidelity.
All icon identities also resolve from the current default kit; no external assets
are supplied or imported.

## Resolve and capture before dependent writes

Resolve the exact current local Image component by name, type, page/ancestry and
native source identity. It is a read-only kit dependency, not a new product source.
Capture the complete default Image paint/fill array, all present paint attributes
(including opacity, blend/scale mode, transforms, filters, rotation, scaling and
image reference), fill-style identity/reference and its currently resolved image
identity. Do not infer defaults from the historical reference, a screenshot,
IMAGE presence, a name match or an image-hash-only comparison.

If the preferred Image component is proved absent, use a suitable available current-kit image/default or an honest variable-bound avatar representation under the shared general substitution policy. Capture the chosen complete paint/style/reference and report the replacement. Do not invent a personal photo, fetch a JPEG, create a style or claim exact current Image parity. Ambiguous identity is a real gap until resolved.

## Apply and verify complete current defaults

Account Item and both Title Block Context APIs retain their declared native
Rich Icon receiver size/shape/mask/stroke geometry. Copy the complete captured
current Image default picture/paint/style/reference through the supported
consumer Image-fill route only. Do not clone or edit the kit master, resize
inherited frames, detach the Rich Icon, create a style or alter its public API.
A matching inherited consumer is read-only.

After writes, reacquire each actual avatar Image and verify complete paint and
style/reference equality to the captured current local default; disclose that
reference snapshot in the result. Preserve receiving native mask/geometry and
Title Block provider badge. Every present paint attribute matters; no hash-only
or solid-color substitution. Actual provider restrictions on an existing object remain precise gaps. If the Image dependency is absent and replaced, compare to the declared captured replacement and mark reference Image-source parity N/A; required avatar-role semantics still must be met.

The current Image snapshot is required for Account Item and Title Block source
builds even when this Dashboard screen uses Standard; recursive Menu/Navigation/
Shell consumers retain that stable source dependency. Assembly-only keeps source
creation inactive and verifies the self-checked compatible current-default
projection. The historical personal-avatar evidence is provenance only, never
an operative image identity, asset delivery requirement or target selector.
