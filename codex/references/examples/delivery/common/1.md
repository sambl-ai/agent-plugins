## General missing-dependency policy

This policy applies within the file mode already admitted above. It never
authorizes automatic adaptation of an unrecognized file.

Resolve the exact current local component, icon, style or typed token first.
Prove absence in its relevant catalogue; an unreadable, ambiguous or restricted
object is not absent. Prefer a suitable available kit alternative, then an honest
owned composition using available kit variables and components. Preserve meaning,
content, native behavior and current-mode compatibility. Missing nonessential
decoration may be omitted without an empty spacer. Never invent a brand asset,
fake a native Slot, detach, import remote primitives, edit kit masters or create
shared variables/styles. Bind available semantic tokens rather than copying HEX,
pixel sizes or font metrics. Disclose replacements before affected work when
known and in the result; this information alone requires no extra approval.
Distinguish a required semantic identity/media role from its preferred graphic.
Keep an available exact original source preferred. If it is proved absent, use a
suitable actual local asset or owned inert identity text, styled with the existing
color variables and text styles, only when the required meaning is preserved.
Disclose lost exact visual/source parity; never invent a brand graphic, lookalike
or fetched replacement. Omit only nonessential decoration. This shared rule
applies to any missing identity/media role, not a per-component fallback list;
keep the explicit adapted qualification in an adapted build.

If no safe compatible construction supplies required meaning or native behavior,
report blocked/incomplete: list actual blocking missing/unsuitable components or
other dependencies by human-readable name, plus unbuilt parts. Preserve completed
work. Unreadable/restricted/ambiguous is not missing. Do not force a substitute or
claim success with unmet requirements.
