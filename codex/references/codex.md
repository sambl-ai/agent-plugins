# Sambl in Codex

This plugin installs the product instructions locally. Read the selected workflow
and only the supporting material needed for the user's request. Use
[the reference index](reference-index.json) to resolve its reference names, paths and exact
canonical versions. Resolve an instruction-only get_reference load to its indexed
local file when that revision is present. The entry's supplied reference/version
context is authoritative for child loads. Do not fetch an already loaded entry
to start it again. Local delivery replaces the separately owned Figma Agent choice
adapter with these Codex rules; source and projected hashes remain in the index.

Live get_capabilities, recognize_kit where the entry requires it, calculations,
proposals, supplied operation status/reporting and feedback remain actual Sambl
MCP calls.
Use only the environment/server/URL declared in this index. Local skills do not
grant access or replace the live authorized capability list. A missing matching
reference may use the existing get_reference fallback with its exact canonical
version; a version mismatch needs the normal update/reconciliation path, not a
mixture of revisions or replayed writes.

Operation-supplied native function references use the same versioned lookup:
reuse matching loaded source or an indexed local module; otherwise call
get_reference with its reference and expectedVersion. Load only needed modules
and continue the same operation. Loading source supplies a dependency for the
existing task. A delegated native
task receives only its goal, relevant facts, preservation criteria and needed
references. When an entry supplies an operation, Sambl retains its state and the
caller uses the supplied completion request.

Examples still obtains the live entry catalogue/packageVersion through
get_example_package. Retain that wrapper and the user's choices; the locally
available entry remains one conversation, not another introduction or approval.
Use the requested package version for its actual dynamic calls and local material
only when its indexed version matches.

For missing Sambl/Figma access, a returned Figma access denial or an unresolved
working file, use
[external-agent preparation](external-agent-setup.md), retaining the original
task. Follow its account/existing-connection fallback before asking for Can edit
or reconnecting. Discover existing Figma plugin/app and MCP tools through the
host's available inventory; a server name or tool prefix does not select the
correct account. The Figma connection is independent of Sambl. Use the actual
installed official Figma skills/tools for native work; do not assume a screenshot or
design-to-code reader can mutate variables. Follow that provider's current skill
requirements and exact API limitations.

For Codex Apps Figma use_figma, the observed limits on 30 October 2026 were
50,000 code characters and 48,000 UTF-8 bytes of serialized return data. Follow
the current provider's limits and safeToRetry/commit semantics; they set call
boundaries, not a required task schedule. After an uncertain write, inspect the
affected state and preserve completed work before continuing.
Calls that switch pages follow the Codex Apps provider's single-page-context
restriction; it is an execution-surface limit, not a common Sambl workflow step.

Use Codex's available user-choice interface for missing material product choices,
or ask directly in chat. A clear bounded instruction or accepted plan can authorize
its covered effects within host permissions, including Apply when that route
supplies it. For a new material choice, expanded scope or required approval, show
the concrete proposal and wait for the user's decision through a supported
confirmation or direct reply. External Send always needs its concrete preview
decision. Tool permission and a generated consent flag are not product decisions.
Question tools restricted to planning or missing input are not required for
approval. A verified no-op needs no Apply question. An unresolved native card is
not answered by a separate ordinary message unless the host actually resolves it.

A host approval/policy rejection is distinct from a returned Figma access denial
or connection loss. Retain the task and preview, and resolve the stated
authorization gap before another dependent write.
Reading status or preparationResult does not remove that denial. Do not retry
or switch provider to bypass that host rejection while its stated authorization
gap remains unresolved. Existing user authorization or new evidence can
resolve the stated concern; neither a recovery response nor a generated consent
flag supplies permission.

An installed skill, available tool, successful OAuth and actual file outcome are
different evidence. Report only what was observed. Restore a failed connection
and reconcile existing work without restarting the product task or repeating
completed changes. If the host requires a new chat after installation, preserve
a compact description of the task, selected target and known result for that
continuation; do not describe the product operation as failed merely by that fact.
